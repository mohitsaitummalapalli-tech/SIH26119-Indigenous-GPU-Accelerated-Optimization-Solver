# Engineering Requirements Specification (SIH26119)

This document formalizes the engineering specifications for the indigenous mathematical optimization solver mandated by SIH 2026 problem statement **SIH26119**.

---

## 1. Mandatory Requirements (Core Constraints)

1. **Zero External Optimization Engine Dependencies**:
   - The solver core must NOT embed, wrap, invoke, subclass, or delegate optimization routines to Gurobi, CPLEX, FICO Xpress, HiGHS, SCIP, CBC, GLPK, OR-Tools optimization engines, cuOpt, or equivalent solvers.
   - All simplex tableaus, interior point solvers, factorization engines, and branch-and-bound managers must be implemented natively.

2. **Core Problem Formulations**:
   - **Linear Programming (LP)**: Continuous variable optimization subject to linear equality and inequality constraints.
   - **Mixed-Integer Linear Programming (MILP)**: Linear objective and constraints with a subset of variables constrained to integer/binary domains.
   - **Quadratic Programming (QP)**: Convex quadratic objective subject to linear constraints.

3. **Modern C++20 Core**:
   - The entire numerical and algorithmic solver core must be implemented in clean, modern ISO C++20.
   - Strictly avoid legacy C-style pointer manipulations where type-safe modern C++ abstractions apply.

4. **Independent Solution Verification**:
   - Every candidate solution generated by the solver must be independently audited for primal feasibility, dual feasibility, and objective accuracy against user-defined tolerances.
   - Return clear certificates of optimality, primal infeasibility (Farkas ray), or dual unboundedness.

5. **Interchange Format Compatibility**:
   - Mandatory native support for parsing and writing standard MPS files (fixed and free format) and LP files.

---

## 2. Target Capabilities (Performance & Scalability)

1. **Sparse Numerical Linear Algebra**:
   - Native implementations of Compressed Sparse Column (CSC) and Compressed Sparse Row (CSR) storage.
   - Sparse Matrix-Vector Multiplication (SpMV) routines optimized for high cache utilization.
   - Numerical scaling and equilibration (e.g. Ruiz equilibration) to improve numerical conditioning.

2. **Multicore CPU Execution**:
   - Multi-threaded linear algebra kernels and concurrent tree search (for MILP branch-and-bound) using native thread pools.
   - Scalable performance scaling on modern high-core-count workstation and server CPUs.

3. **GPU Acceleration (CUDA)**:
   - GPU-accelerated sparse matrix operations and linear system solves for problems where matrix dimensions amortize PCIe transfer overhead.
   - Explicit memory management between host and device without unnecessary synchronization stalls.

4. **Numerical Robustness**:
   - Dynamic threshold pivoting in LU factorization to handle numerical instability and ill-conditioned bases.
   - Graceful detection and reporting of numerical singularity and degeneracy.

5. **Benchmarking & Validation**:
   - Automated benchmarking against standard optimization problem libraries (Netlib LP, Mittelmann benchmarks, MIPLIB).
   - Direct execution time and solution quality comparisons against reference solvers to measure performance gap and progress.

---

## 3. Future Extensibility (Post-Core Enhancements)

1. **Advanced Presolve Reductions**:
   - Dual bound tightening, probing, and constraint clique aggregation.

2. **Mixed-Integer Cutting Planes**:
   - Implementation of Gomory mixed-integer cuts, mixed-integer rounding (MIR) cuts, and knapsack covers.

3. **High-Level Language Bindings**:
   - Thin C-compatible foreign function interface (`extern "C"`) enabling downstream Python (NumPy/PyData) or Julia bindings.

4. **Multi-Platform Portability**:
   - Full support for Linux x86_64, Windows x86_64, and ARM64 architectures.
